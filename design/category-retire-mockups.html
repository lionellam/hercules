Retiring categories

Mockups for retiring a category instead of deleting it. A retired category isn't offered for new expenses, but past expenses keep it, and it can be restored at any time. Nothing is removed from the database. These use the app's own styles; nothing in the app has changed.

Blue dashed outlines mark what's new. New marks a new screen state; Unchanged shows how an existing screen looks with a retired category.

1. Retiring a category

The Retire button sits where Delete sits on an expense, in red on the left. It's labelled "Retire" rather than "Delete", because nothing is removed. A confirmation explains what happens, using the same kind of prompt as deleting an expense.

2. Retired categories on the Categories screen

Retired categories move to a collapsed "Retired" group at the bottom of the list, so they're out of the way but easy to bring back.

3. Past expenses in a retired category

History, the Today list and Summary keep showing the category's name. The only visible change elsewhere is in the edit sheet, so an old expense can still be opened and saved.

Unchanged

  • Log screen: retired categories aren't offered to the parser, so new entries go to the closest active category or "Other". The review card lists active categories only.
  • Today list, History and past months on Summary show the category's name as before.
  • Renames still carry through history, and no text copy of the name is added to each expense.
  • No permanent delete: a category is never removed from the database.
