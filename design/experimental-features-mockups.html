Experimental Features

A page in Settings listing features that are built but not yet switched on for everyone, each with a switch. Phone size, light appearance unless marked. The feature names on the page are examples only, to show the layout; the real list would hold whatever is being tried out at the time. Dashed blue outlines mark what's new.

1 · Getting to the page from Settings

Two ways in. Either way, only the app owner's account would see it (see the notes at the bottom).

2 · The Experimental features page

Opened from the row above, with "‹ Settings" to go back, like Categories & budgets and Currency. Each feature has a name, a one-line description and a switch; a change takes effect straight away, with no saving step.

Points to decide (discussed in chat)

1. Who can see the page

  • Owner only (recommended): the server checks the signed-in account against an owner setting kept in Vercel and web/.env.local, never in the repository. Invited family and friends never see it.
  • Everyone: any signed-in person can try the features.

2. Where the switches are remembered

  • On the account (recommended): saved in the database, so a switch turned on at the computer is on at the phone too. Needs one new column, added in Neon by the owner as before.
  • On the device: no database change, but each phone and browser has its own settings.

3. What a switch can and can't do

  • A feature's code still has to be built and deployed once, hidden behind its switch. After that it can be turned on and off as often as needed without another deploy.
  • A feature that needs a database change still needs that change first.
  • When a feature graduates, its switch is removed and it's on for everyone (a normal version bump); when one is dropped, its code and switch are removed.
